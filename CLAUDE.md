# tree-sitter-golang

Tree-sitter grammar for Go, at the language version of Go 1.27.

## Reference

- The authority is the Go language specification, `doc/go_spec.html` of the Go release (`$(go env GOROOT)/doc`), and
  the two parsers of that release: `go/parser` and the compiler's `cmd/compile/internal/syntax`. Settle each grammar
  question there.
- The grammar is a clean-room implementation. No file, rule, or test comes from another Go tree-sitter grammar. Do not
  read one when you change this grammar.
- An input that both parsers accept parses without ERROR or MISSING nodes, and its tree has the structure of the
  `go/ast` tree. An input that either parser rejects produces ERROR wherever the grammar can see the defect.
- The grammar accepts what both parsers accept and only the type checker rejects: any expression as a statement, a
  type literal or `~x` as an operand, `[...]T` outside a composite literal, a non-name left of `:=`, `.(type)` outside
  a type switch, an expression in a type switch case, and a constant with a type and no value.

## Where things live

- `grammar.js` - the productions of the specification. `expressionSpine` builds the `header_` copy of the expression
  and simple statement rules, which forms the operand between `if`, `for` or `switch` and the block.
- `src/scanner.c` - the automatic semicolon, and the empty markers that keep a token on the line of the token before
  it: `_same_line`, `_brace_on_same_line`, `_element_end`, `_colon_on_same_line`. Where a line ends after a list
  element, it returns `_line_break_after_element`, which no rule accepts.
- `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` - generated by `tree-sitter generate`
  with tree-sitter CLI 0.27.0. Never edit them by hand. Regenerate with that CLI version, and make a CLI upgrade its own
  change.
- `test/corpus/` - corpus tests, one file per topic. `:error` marks an input that must produce ERROR.

## Rules

- Keep the `externals` array in `grammar.js` and `enum TokenType` in `src/scanner.c` in the same order.
- Go inserts a semicolon at a line end after an identifier, a literal, `)`, `]`, `}`, `++`, `--`, `break`, `continue`,
  `return` or `fallthrough`. A new position after such a token where no terminator is valid takes `_same_line`,
  `_brace_on_same_line`, `_element_end` or `_colon_on_same_line`.
- An empty statement, the empty initializer and condition of a `for` clause, and a label without a statement end with
  an explicit `;` only, because Go inserts no semicolon after `;`, `{` or `:`.
- The generator copies the fields of an aliased hidden rule into the parent node, and `child_by_field_name` on the
  parent then returns the wrong child. A rule that has fields and appears only under an alias gets a visible name.
- Dynamic precedence settles the parses that both stay valid: a type parameter list against an array length (as
  `isTypeElem` in `go/parser`), `<-` before `chan` (as the re-association in `go/parser`), and an expression switch
  over `.(type)`.
- Every keyword is in `KEYWORDS`, the reserved word set; an identifier never matches one.
- Every corpus input without `:error` passes both parsers, and every `:error` input fails at least one. Check a new case
  with both parsers before you add it.

## Verification

- After a change to `grammar.js` or `src/scanner.c`, run `tree-sitter generate` and `tree-sitter test` in this
  directory, and commit the regenerated `src/` files with the change.
- After a change to `grammar.js` or `src/scanner.c`, also parse the Go distribution:

  ```sh
  find "$(go env GOROOT)/src" "$(go env GOROOT)/test" -type f -name '*.go' > /tmp/go-files.txt
  tree-sitter parse --paths /tmp/go-files.txt --quiet --stat
  ```

  Only a file that `gofmt -e -l` reports as an error, or that the compiler rejects, may fail.
